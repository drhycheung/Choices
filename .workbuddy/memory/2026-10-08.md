# 2026-10-08

## Choices 项目启动 — 同类开源项目调研

目标：开源教育工具「文字交互式分支叙事模拟器」。核心引擎通用，场景作为独立数据包可不断新增。
首个场景=学生创业（植入国家安全/法律/伦理风险抉择），后续扩展实习、科研等。

### 关键可借鉴项目
- **Liberty Park Scenario Engine**（Streamlit/Python，MIT）：最贴近的蓝图。数据驱动 JSON config.json 每个场景（公民/宪法/法律主题），变量追踪倾向分、条件分支、多结局类型（成功/失败/妥协）、反思题、学生进度导出。架构可直接迁移到国家安全/法律/伦理情景。
- **NetStrider/text-adventure-engine**（Python）：通用引擎+JSON 场景（scenes/choices/conditions/effects，flags/stats/inventory/endings），effects 迷你 DSL。几乎就是"引擎+数据包"设计。
- **Aditya-Raval/cyoa**（Go，MIT）：JSON 章节=路由，零依赖 Web 服务。
- **choiceStoryApp**（原生 JS，MIT）：JSON 场景、XSS 防护、localStorage 存档、跨平台。
- **Ink**（Inkle，MIT）：分支叙事脚本语言，变量/条件，编译为可嵌入 JSON，工业级。
- **Twine**（GPL-3.0）：可视化节点编辑器、导出 HTML，但 copyleft。
- **ChoiceScript**（Choice of Games，MIT）：*choice/*if 标记语言，内置 Quicktest/Randomtest 全路径测试——对教育内容 QA（保证无死路、每条路径都有结局）很有价值。
- **pathtocoexistence**（Twine）：AI 治理模拟，3 种取向×累积评分→3 结局，演示"累积选择→结局"模式。

### 架构结论
1. 引擎/场景分离是已被验证的模式，用户设想正确。
2. 场景 JSON 应支持：文本+选择、选择条件（门控/隐藏）、选择效果（变量增减）、多结局类型、反思题。
3. 需做"路径校验器"保证无死路、每条路径都有结局（借鉴 ChoiceScript 测试思想）。
4. 许可证优先 MIT/Apache-2.0；Twine 为 GPL，若直接改其代码需同开 GPL。

### 设计取舍：NetStrider vs Liberty Park（用户问"哪个最好"）
- 结论：**二者互补，不二选一**。
- **引擎架构以 NetStrider 为蓝本**：干净的"通用引擎 + JSON 数据包"分离，conditions/effects 迷你 DSL 正好用来追踪 国家安全/法律/伦理 风险维度评分；含校验与测试，工程底子好；不绑定框架，便于另搭 Web 播放器。缺点：纯 CLI、无教育层、0 Star。
- **场景 Schema 与教育层以 Liberty Park 为蓝本**：config.json（metadata/variables/scenes/reflection）、多结局类型（成功/失败/妥协）、反思题、学生进度导出——NetStrider 缺这些。缺点：Streamlit 应用耦合重，不是干净的"可插拔数据包"抽象。
- 二者均 0 Star、偏未成熟，定位是"取模式"而非"fork"。

下一步：用户确认是否采用"JSON 数据驱动引擎（类 Liberty Park/NetStrider）+ Web 界面 + 校验器 + 反思层"的路线并搭建脚手架。

### 补充调研（23:1x）— 更贴合"静态+JSON数据包"的新项目
- **librogame-engine**（Z4RD0Z, MIT, 原生 HTML/CSS/JS）：story.json 驱动、无构建、可直接部署 GitHub Pages/itch.io；节点/选择含 requirements(条件)/effects(变量增减)/oneshot。结构上最接近目标，但含 TTRPG 2d6 骰子（游戏化，教育确定性评分需去掉）。
- **storylet-framework**（wildwinter, MIT, JS/C++/C#/Python）：形式化"独立数据包"模式——storylet(条件门控的内容块)+packet(JSON 集合)。这正是"场景即独立数据包"的理论化命名，值得作为架构参考。
- **NamelessStory**（NamelessProj, MIT, React/TS）：单 JSON 故事文件 + **运行前自动校验并报错清单** + 可部署 GitHub/Vercel；其"校验器"实现是用户想要的路径校验器好范本。
- **iffinity / Fractive / Dendry**：均"编译为单一独立 HTML"的静态路线（Fractive 为 AGPL-3.0 需注意 copyleft）。
- **WebGAL**（MakinoharaShoko, MPL-2.0, 中文社区, 3300+★）：现代 Web 视觉小说引擎，浏览器运行，中文文档——中文 Web 叙事引擎代表，可作语境参考（偏视觉表现）。
- 额外客户端 JS 引擎：Undum / Raconteur / Tuesday JS / QuestJS / Squiffy / Narrat Engine。
- 排除：**Tadpole**（Django+SQLite+Docker，服务端，不满足静态要求）。
- 结论：新三项最值得吸收 = storylet 模式（独立数据包理论）+ librogame 的 JSON 形状 + NamelessStory 的校验器。
